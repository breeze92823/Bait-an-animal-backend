# Bait an Animal — BACKEND (game server)

Frontend (3D client) lives at `../Bait-an-animal`. Colyseus + Mongo, started from the Bowling Roll server; its race roster, spin wheel, daily reward and leaderboards were removed because this game never used them (they are in the template's git history if a later feature wants them). Presence was rebuilt for this game: 5-player rooms, one plot each (below).

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22. Local test with the client: `bait-backend` launch config (port 2571) + `bait-shop` (frontend on 5297 pointing at it).
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { token, username, pfp })`). Client-authoritative: the server only bounds/sanitises saves (`src/baitSave.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- Signed-in players' only save is this server's Mongo doc (the client's `net.js` stops writing localStorage for them). Guests (`guest-` ids) and runs with no server configured keep their save in the browser (localStorage, client `SAVE.key`); a guest who signs in to a NEW account brings it along, an account that has a save loads that instead.
- Messages client -> server: `saveProgress { save }` (the game's whole state `S`, throttled client-side to every `NET.saveEvery` s + on tab hide/close), `identify` (`{ token, username, pfp }` after a sign-in/out mid-session; a username/pfp-only identify skips the token check), `adReward { rewardToken }` (rewarded ad: verified with Boxity, answered privately `adReward { ok, potion: 'cash', minutes: 10 }` or `{ ok: false }`). Server -> client (private): `progress { save, serverTime }` (the stored save, sanitized), `noProgress { serverTime }` (new account, guest, no database, or a document without a save: the client keeps its fresh state and saves it), `serverError` (the save could not be read: saving stays off so it is never overwritten). Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted. Roster (`PlayerState`): `username`, `signedIn`, `pfp` (http(s) only, max `PFP_MAX_LEN`), and presence (all visual, client-reported, only bounded): `plot` (0..`PLOT_COUNT`-1, unique, assigned on join by `freePlot()`, kept through a reconnect, freed on leave), `x y z yaw speed vy grounded` (`move`, ~10/s, own frame: the player's plot at x = 0; numbers clamped to `POS_MAX`/`SPEED_MAX`), `look` (`look { look }`: JSON outfit key + equipped ids + proportions, `LOOK_MAX_LEN`), `pen` / `mach` / `hook` (`base { pen?, mach?, hook? }`: JSON blobs, must parse, `*_MAX_LEN`), `hx hy hz` (the hooked catch, in `move`). `fx { t, d }` (t in `FX_TYPES`, d <= `FX_MAX_LEN`, `FX_PER_SECOND` per player) is relayed to everyone else as `fx { s: sessionId, t, d }`; `test/Presence.test.ts`.
- **The save** (client game.js `S`, stored as the doc's `save` field `{ _id, username, save, version, updatedAt }`) is bounded by `src/baitSave.ts` `sanitizeSave` (money/counters clamped, ids match `ID_PATTERN`, equipped pets must be owned, timers at most a year ahead, unknown keys dropped; `test/BaitSave.test.ts`). **Every key of the client's `defaults()` in game.js must be listed in `sanitizeSave`, or it is silently lost on reload** (a new `S` field = add it there + a test, and bump `SAVE_LIMITS` if a cap changes; the id maps hold up to `SAVE_LIMITS.ids` = 128 keys, the client has 63 species). Today: `money earned catches selected baitReady indexSeen freeClaimed packBought nextShot offerEnds packEnds lastSeen machine baits up passes potions claimed auto animals pets index best gym`.
- `src/constants.ts` bounds must cover the client's `src/config.js` (ids match `ID_PATTERN`, money up to `CURRENCY_MAX`). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` read from `src/constants.ts` = `PLOT_COUNT` = 5 (one player per plot). Never `seatCap`: the SDK docs say Boxity sizes pods itself (the older hosting page still shows seatCap; the SDK docs win). Party play needs maxClients 2-100; a party bigger than 5 can't fit. Needs repo var/secret `LEGION_GAME_ID` (= `bait-an-animal`, the client's `GAME_SLUG`) and secret `LEGION_DEPLOY_TOKEN`.
- **Server identity (Boxity REQUIRED)**: `WorldRoom.onAuth` verifies the join's Boxity token (`src/boxity.ts` `verifyGameToken`: POST `{BLOXITY_API_URL}/v1/auth/game-token/verify`, Bearer token, `{ gameSlug }`) and ONLY the returned `user._id` is an account (saves, eviction, leaderboards, stats); no token / refused / platform down = a guest. A `userId` in the join options is ignored; never add a fallback to a client id (Boxity's `audit_sdk` blocks publishing). The verified id is public as `PlayerState.uid` (clients match chat bubbles by it); the verified name/pfp/outfit key win over the client's. Tests fake the platform: `test/server.ts` verifies token `t-<id>` as account `<id>`.
- **Boxity reporting** (all no-ops without the injected `BLOXITY_REPORT_TOKEN`, so local runs and tests send nothing): `src/legion-room-reporter.ts` (the Open Rooms directory, every 2 s, needs `MATCHMAKER_REPORT_URL`); `src/leaderboards.ts`: boards `earned`/`catches` (weekly sums of what an accepted save gained since the session's loaded baseline) and `strength`/`index` (all-time bests), flushed every 15 s to `/v1/leaderboards/hosted/{gameId}/report`; profile stats Cash / Animals Caught / Strength / Pet Index (current values, above-ceiling values left out) every 60 s to `/v1/games/{gameId}/stats`; both from server-accepted saves only, `legion_<id>` identities only, flushed on SIGTERM (`src/index.ts`). The client declares the same board ids (`LEADERBOARDS` in its config). `test/Boxity.test.ts`.
